# Drum circular loop refinement

1. **Activation context.** The loop controller routes manual taps, external receivers and loop scheduling through activateDrum with explicit activationSource values manual, trigger and loopPlayback. All share admission, receiver-owned sound selection, voice deduplication and musical feedback. Simultaneous manual admission promotes transient feedback without playing a duplicate voice.
2. **Manual recording.** Only manual context updates canonical DrawGrid authored notes. Taps retain strict forward 48-tick quantisation. Repeated playback never writes the pattern. Persistence reconstructs markers from authored notes; external activations carry no persisted pattern data. Existing saved patterns remain intact because their historic hit origins cannot be recovered.
3. **Triggers.** Ball and Ripple retain receiver timing and quantisation and use the receiving Drum instrument. They animate the pad but add no remembered marker. Ripple across all six kit members left the two existing manual patterns unchanged. Ball collision with the Hi-Hat sounded HI-HAT CLOSED while its pattern stayed empty.
4. **Circular timeline.** A code-native SVG outside each pad replaces the expanded rectangular timeline. Subtle empty dots, stronger authored hits and a warm moving dot keep the instrument visually dominant. Authored hit markers pulse on manual performance and replay; transient triggers only pulse the pad.
5. **Canonical mapping.** Each marker uses col * 48 ticks, divided by periodLoops * 384. Clockwise angle is tick / totalTicks * 2?; coordinates are (64 + 58 sin(angle), 64 - 58 cos(angle)). Zero is noon. There is no separate UI rhythm model.
6. **Multiple loops.** The same circumference holds 8, 16, 24 or 32 slots. Every eighth slot marks a quiet toy-loop boundary. The four-loop Kick was checked in the browser with 32 markers and quarter divisions.
7. **Playhead.** Animation frames read controller.phase, which reads Heartbeat ticks. No UI clock accumulates time. Pause freezes phase, Return to Start places all indicators at (64, 6), and BPM changes alter traversal speed through the transport. Tests cover pause/resume, reset/downbeat and BPM continuity.
8. **Clear.** Revealed controls use expressiveControl kind clear and the shared broom icon. Clear empties canonical notes immediately, cancels pending remembered playback and leaves position, instrument, volume, period and transport phase intact. Pending transient triggers survive Clear. Browser checking confirmed zero persistent markers, a retained playhead and four-loop period, followed by a fresh manual hit.
9. **Drum Set readability.** Six ordinary independent Drum objects each show their own ring. At the tested 1374 ? 861 viewport the four-loop ring remained separate from the pad and neighboring kit members; small empty markers stayed quiet and recorded hits remained stronger. Existing connection wires can cross the kit independently of these rings.
10. **Validation.** 115 targeted Node tests passed across Drum, loop/ring UI, Ball, Ripple and creation palette. Browser QA covered multiple manual taps and repeats, observed marker and pad animations, Ripple through the kit, Ball into Hi-Hat, Clear/fresh recording, save/reload, four-loop density and Return to Start. Scheduled note observations showed no duplicate id/time pairs. Audio analyser peaks reached approximately 0.275 during trigger checking and 0.159 after reload. These are measured browser audio observations; no human listening assessment is claimed.
