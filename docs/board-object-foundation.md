# Shared Board Object foundation

The shared spatial layer is `board-object.js`, with the live board API in `board-object-layer.js` (`window.BoardObjects`). The existing physical, container, and Art stores remain adapters and lifecycle authorities. Their BoardObject views are regenerated from current authored values so dragging, editing, and restoring cannot leave a second spatial store out of sync. No UI or graph replacement was introduced.

1. **Schema:** version 1, stable `id`, `kind`, logical `transform` (`x`, `y`, `rotation`), `bounds`, `appearance`, `capabilities`, `references`, `owns`, and `authoredState`. All four examples use `createBoardObject`; its kind registry also supports the existing persistent ball shell. Views are detached copies. Existing IDs are retained.
2. **Capabilities:** a small parameter map. Cube has draggable, box physicsBody, triggerReceiver, pitchSource.midi. Cannon has draggable, triggerEmitter, instrumentSource.instrumentId. Simple Paint has draggable and loopSource. Decorative Art has draggable and decorative. The vocabulary also reserves playable. There is no scripting or editable capability UI.
3. **Authored/runtime:** physical authored records and runtime values live in separate maps. Velocities, playback links, glow, hover, flash, animation phase and drag state are omitted from authored snapshots and discarded on restore. The compatibility `snapshot()`/`get()` APIs still expose runtime values to current callers; persistence uses `authoredSnapshot()`. Bouncer sessions, flight caches and previews stay in the controller. Canonical capture geometry is retained as capture data, not current simulation state.
4. **Ownership/references:** `owns` identifies the existing container's canonical musical internals. `references.cubeIds` and `references.triggerIds` identify external cubes and ball shells. The board layer delegates removal to the established owners. Cannon deletion removes owned captures but leaves referenced cubes. Cube deletion preserves captures and marks them stale. Paint deletion removes owned DrawGrids. Reference queries return explicit `{id, role, status: 'missing'}` entries, and resolve again if the object returns. Load also recomputes Bouncer broken references.
5. **Resolver:** `resolveBoardInteraction(emitter, receiver, timeSeconds)` checks capabilities only; no ball/cube kind checks. Contact time supplies timing, receiver pitchSource supplies MIDI, emitter instrumentSource supplies timbre. Missing capability, pitch, instrument or finite time produces no event. Bouncer's canonical DrawGrid conversion invokes this resolver. Physics attaches the contacted receiver's capabilities; pre-foundation captures have an explicit legacy pitch-to-capability adapter. Sweep detection, hit suppression, tick quantization, phase and transport remain unchanged.
6. **Cube:** `physicalBoardObject` projects the existing authored geometry and pitch. Cubes own no active instrument. Current colors, dragging, collision bounds, independent IDs and sharing remain in the existing implementation.
7. **Cannon/ball:** cannon is an authored BoardObject backed by its container, with position, direction, speed, instrument and phrase length. Fired motion is a runtime trigger body. The existing reusable/persisted ball shell retains its ID and authored resting position for compatibility; velocity and capture links are reconstructed. Deleting a cannon still cleans up its unshared fired shell through the existing lifecycle handler.
8. **Simple Paint:** the container is a `simple-paint` spatial object. Its owned DrawGrids remain the musical/content authorities; content IDs are exposed in authoredState. Gesture history stays in existing container interactionData. DrawGrid notes, silence, Heartbeat, Sequence, topology and their persistence are unchanged.
9. **Decorative Art:** Flash Circle is the regression example. Base Art panels expose a live BoardObject getter from authored CSS positions/sizes; saved Art envelopes include that view. Default spatial capabilities contain no pitch, instrument, playable or emitter capability. Existing Art visuals and optional internal music workflows remain separate; adapting the spatial shell does not turn visual reactions into sound.
10. **Save migration:** scene schema advances from 2 to 3; embedded BoardObjects have their own version 1. Existing envelopes are retained for compatibility. Legacy physical/container/Art records acquire their views automatically, without ID replacement. Old Cube instrument data is removed. Existing Bouncer v1/v2 migrations remain in place; all Bouncer versions then reconstruct runtime ball links and recompute missing references. Embedded views are derived metadata, not an independently editable duplicate of the adapter's authored data.
11. **Remaining special cases:** shape-specific swept box physics remains in Simple Bouncer, as does its drag sweep correction. This pass generalizes musical resolution, not geometry dispatch. Current cannon controls, instrument latching, capture invalidation, graph ownership, and Art visual routing remain specialized to preserve behavior. Existing UI creation flows continue using their established factories; the common board API delegates to those same factories rather than introducing alternate implementations. Full migration of all legacy save envelopes to standalone BoardObject documents is deferred.

Validation: focused BoardObject tests cover stable identity, capability composition, kind-independent resolution, silence for decorative/missing capabilities, actual capture conversion, legacy records, runtime separation, save round trips, coexistence, and missing references. Existing Container/Bouncer/Paint suites cover musical ownership and deletion. Existing viewport/zoom and Art suites cover logical positioning and cleanup.

The expanded regression run found two pre-existing `simple-paint-interaction.test.mjs` assertions expecting `LINE_EXISTS`; the unchanged HEAD controller returns `DRAWING_EXISTS`. These are not changed by this architectural pass.

Final verification: 122 tests passed across BoardObject, Simple Bouncer, Container Toys, Simple Draw, board interactions, board zoom, Art dragging/viewport, and DrawGrid persistence cleanup. Syntax checks passed for both new modules and main.js; `git diff --check` passed. Browser smoke testing on a fresh local origin exercised Bouncer creation/aim/fire, Paint drawing/playback, Flash Circle creation/movement, and coexistence after reload, with no console errors. Full browser edit/delete interaction sequences and audible output were not exhaustively verified; deletion/reference behavior is covered by model tests.
