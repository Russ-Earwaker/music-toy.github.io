# Drum Set spawn safety and Simple cable hierarchy

1. **Footprint.** Before any Drum is created, the full six-pad layout is projected to one logical rectangle. Relative to the kit center it spans x = -415 to 349 and y = -234 to 234 (764 ? 468 board units). This includes the circular rings and always-visible left handles. All members receive exactly the same translation; no compression or scattering occurs.
2. **Search.** Start at the usual creation point. Test the desired column and columns aligned beside obstacle edges. The shared vertical-slot solver finds the nearest clear row for each, then choose the smallest squared Euclidean displacement with deterministic tie-breaking. The desired location wins whenever clear. This operates in unbounded board coordinates, without viewport clipping, zoom or DPR inputs. Crowded boards can place a kit partly offscreen rather than on existing toys.
3. **Padding.** Keep 24 logical board units between the complete kit footprint and existing bounds. Existing Drums include their visible handles/rings as obstacles. Creation does not move existing objects or request global rearrangement.
4. **Shared helpers and bounds.** nearbyFreeRect reuses graph placement's clearVerticalSlot and rectanglesOverlap. The application supplies canonical BoardObject geometry for Drums, Cubes, Balls, Ripple emitters, Simple Paint, Cannon and Art, supplemented by normal music/Art panel bounds from the existing graph adapter. Hidden contents of closed containers are excluded; the container surface remains an obstacle. The default model-only entry point also avoids existing Drums.
5. **Simple lines.** Mode-level CSS sets connection-path opacity to 0.25 under html[data-ui-mode="simple"]. Lines remain present. Advanced inherits the existing full-opacity appearance. No transport, timing or topology changes were introduced.
6. **Activity.** The existing renderer exposes its current pulse state on the cable group with data-active. Simple active paths use opacity 0.8 and retain the existing wider/brighter stroke and transition halo (opacity 0.55). Disconnected paths follow existing removal behavior; no new faint ghost connection is added.
7. **Validation.** 97 focused Node tests passed: full-footprint admission, obstacle collection, deterministic logical placement, fixed relative layout, consecutive kits, existing-object preservation, graph placement, Drum behavior, connection rendering and mode/topology preservation. In browser QA, two Cubes and a Ripple occupied the requested area; the first kit translated nearby, and the second found another free position. The first kit's coordinates stayed identical. Simple ? Idle lines visually receded while activity stayed distinct. Other object types were covered through the bounds adapter tests rather than individually spawned in browser QA.
