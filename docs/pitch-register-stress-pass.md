# Pitch/register stress pass

DrawGrid now has Advanced → Musical → Register: −2, −1, 0, +1, +2 octaves. It is a separate persisted toy offset, `registerOctaves`. Canonical `{id,col,sourceMidi}`, source geometry, rows, ticks and strokes are unchanged by Register.

1. **Range tested.** Browser gestures and explicit fixtures cover MIDI 48–81 (C3–A5). Automated projection tests cover all 36 chromatic rows, MIDI 48–83 (C3–B5). Register ±2 produces MIDI 24–105 (C1–A7) from the tested source range. Browser playback specifically verified ±1; ±2 is covered in the pitch-function and persistence tests.
2. **Representation.** Generated DrawGrids use the existing fixed 800×600 logical canvas and 36 rows over the 540-unit safe grid height: 15 logical units per semitone. Observed source-node centers span Y=67.5…562.5. Each chromatic pitch has a distinct row; no octave folding, inversion or collapse.
3. **Clipping/readability.** Smooth-stroke samples remain inside the grid, and pass through exact node positions. The full-height gestures, multi-grid spiral and four-bar phrases retained ink. At Overview scale the contour is recognisable, but semitone editing and labels require the existing normal zoom. Long horizontal chains and several vertically stacked phrases require board panning; the screenshots show viewport cropping of whole toys, not pitch clipping inside a toy. Existing DRAW overlays and connection lines can clutter Overview. No broad UI change was made.
4. **Octave editing.** Explicit browser fixture: A4 B4 C5 D5 D5 C5 B4 A4, with logical Y values 247.5, 217.5, 202.5, 172.5 and reverse. B4→C5 stays monotone. An actual generated C5 was dragged to C♯5, down to B4, and back to C5, retaining its ID. With Register +1 these scheduled as C♯6/B5/C6. All 24 grids in the final QA scene retained exact canonical notes, stroke arrays and Register after reload.
5. **Register semantics / pipeline audit.** Existing pipeline is source → instrument octave policy → harmony adaptation (including its existing optional register-fitting policy) → graph transpose + Local Transpose → sample/tone. Added Register contributes exactly 12×registerOctaves at the final transpose boundary. The pre-existing harmony `register:{minMidi,maxMidi}` argument is distinct and unchanged. This preserves existing zero-setting semantics, keeps harmony policy unchanged and adds the same octave offset to every pitched event. Percussion ignores it. Ordinary DrawGrids retain their legacy instrument octave policy; generated grids retain source register through existing authoredPerformanceOptions. Preview and scheduled playback share this boundary. Register is per toy; a generated multi-grid chain consists of independent toys.
6. **Framing.** No automatic vertical framing was necessary for the tested source range. Register changes performed pitch; the editor deliberately stays in authored pitch space, and its tooltip says so. This keeps drag targets stable when Register changes. A source C5 remains displayed as source C5 while sounding C6 at +1.
7. **Overflow indication.** None added: every tested source pitch and its curve fit. Higher/lower indicators would falsely imply hidden source notes here. Arbitrary imported source pitches beyond a grid's declared pitchRange were not established as supported by this pass.
8. **Straighten comparison.** Browser rise, fall, repeated crossings, broad spiral, abrupt reversals and capped four-bar sweep were Straightened. The same high/low order persists through ordinary grid chunks. Automated checks compare every musical node against Straighten and the normal smooth-stroke points. Partial final chunks remain partial (browser examples: 102, 105 and 154 ticks); capped phrases remain four 384-tick chunks, 32 notes. Original gestures remain unchanged under Register and morphing.
9. **Scale mismatch.** Free Play retains C-major pentatonic; normal DrawGrid drawing retains C-minor pentatonic. Existing-node dragging is chromatic: the browser generated C5 could become C♯5 or B4 without a second pentatonic quantization. Adding/redrawing normal strokes can therefore introduce a different pitch collection from Free Play. This policy difference remains intentionally unresolved. B4 is absent from the Free Play pool, so the explicit sequence uses a clearly identified programmatic canonical fixture.
10. **Evidence and limits.** [Per-node JSON](../resources/debug-output/free-play/pitch-stress-nodes.json) and [CSV](../resources/debug-output/free-play/pitch-stress-nodes.csv) record 162 generated/fixture nodes: normalized source Y (null for explicit fixtures), sourceMidi, grid index, step, tick, stable ID, logical Y, Register, actual preview pitch, sequenced source pitch and actual performed pitch. Every node has both real preview and scheduled audio events, with zero preview/schedule pitch mismatches. These are event-level sampler inputs, not microphone recordings. Preview was invoked by a temporary QA button dispatching the ordinary drag-end event for each node while stopped; browser pitch editing used actual pointer drags. No application errors were captured.

Full-height movement takes several steps because musical time is sampled by path distance. A gesture cannot alternate minimum/maximum on *consecutive* 48-tick steps under that rule. Browser abrupt reversals exercise the real gesture mapping; a second canonical fixture and automated 1100/1536-tick fixtures exercise consecutive-step C3/A5 extremes without changing timing policy.

Register 0→+1→−1→0 preserved exact source notes and stroke arrays. A normal linked copy inherited +1 and the same eight note IDs in the browser. Automated shared-controller tests verify ±1/±2/0 publication and sibling hydration without rewriting pitches. Browser editing the copied control was not established: overlapping toy placement intercepted the attempted opening of its Advanced shelf. Linked-state synchronization itself is covered by regression tests.
