# Parallel Simple Paint presentation experiment

Current routing: the independent [GPU field experiment](SIMPLE-PAINT-GPU-FLUID.md) now handles High; the particle prototype remains available with `highBackend=particles`. The sections below record the earlier architecture passes.

This records the initial quality experiment. High's original screen-sized geometry is superseded by the [world-space zoom fix](SIMPLE-PAINT-ZOOM.md); Standard retains its original behaviour.
The subsequent [disturbance-lit density pass](SIMPLE-PAINT-LIQUID.md) replaces High's direct particle rendering with accumulation, blur and liquid shading.

1. Architecture: `renderQuality` is a runtime-only export in `src/runtime-config.js`, separate from the preset manifest and project state. Standard remains the default. `simple-draw-creation.js` changes only its presentation factory import/call. The current Canvas module is untouched by this pass. High modules load dynamically only after a High gesture needs them. No user preference is persisted.

2. URL switches: `index.html`, `index.html?quality=standard`, and `index.html?preset=simple-playtest` use Standard. `index.html?quality=high` and `index.html?preset=simple-playtest&quality=high` request High. Unknown values use Standard. Reloading switches quality; there is no new settings UI.

3. Interface: the input layer continues calling `begin(worldPoint)`, `move(worldPoint)`, `release()`, `stop()`. The adapter captures transient visual state, forwards these calls to the existing Standard implementation, or feeds state to High's `consume(state)`. `getProof()` exposes diagnostics; `destroy()` disposes the adapter; `ready` supports deterministic fixtures. Lazy-load queues preserve timestamps and cancellation clears pending input. A fallback replays only visual input, never musical commits.

4. Shared state: event/time, world pointer, recent world velocity, transient gesture path, drawing/release state, instrument and its shared `instrumentColour`, board transform, shared radius, reduced motion, and fixed Draw tool metadata. Path points are copied and presentation code cannot mutate authored input. Generated nodes, audio scheduling and saved objects are intentionally absent: this prototype changes only the active gesture medium. Authored paths, notes, controls and hit targets remain the existing DOM/Canvas implementation in both modes.

5. Technique: no engine or external dependency. High uses a CPU 28×28 velocity/density grid plus 1,800 particles (900 coarse pointer), damped rest springs, coarse pressure gradients and neighbourhood velocity matching. A speed cap of 105 CSS px/s prevents launch trajectories. Swept circle exclusion displaces particles without converting correction into velocity. WebGL2 draws soft overlapping density splats and small suspended cores in two point-sprite passes, plus a faint rim. The browser converts the existing OKLCH/hex instrument colour into RGB. No full fluid solver, framebuffer feedback, floating-point texture extension or offscreen framebuffer is required.

6. Radius: both use `DRAWGRID_POINTER_SCREEN_RADIUS`, currently 48.6 CSS px. World positions go through the same board transform; the circle stays screen sized across zoom/DPR. High uses a transparent fixed board overlay with the same pointer transparency and stacking level as Standard. A per-document `HighQualityBoardRenderer` owns one surface and supports registering multiple visual effects; only Paint is implemented. Registered effects currently have their own animation callbacks, a deliberate prototype limit if many future effects are added.

7. Fallback/lifecycle: unsupported WebGL2, shader/link/allocation failure, runtime exception or context loss switches to Standard with a clear warning. Reduced motion uses Standard. The WebGL canvas/context/buffers/shaders are created on begin and released when the last effect stops. Context loss cancels the effect and falls back rather than attempting an invisible repair. No GPU loop runs while idle. Release returns material inward and fades for 1.4 seconds, then cancels animation and removes the surface. Visibility/cancel/scene transitions use the existing stop path. Resize and DPR changes resize the drawing buffer on the next active frame, capped at DPR 2.

8. Comparison: open `experiments/simple-paint-webgl/index.html`. Equal-width Standard/High panels receive identical world paths and timestamps from one synthetic clock. Controls: Slow, Fast, Pause, Sharp Turn, Loop, Release, Clear, instrument, zoom, pan, freeze/resume and fixed 0.5-second advancement. Each panel shows effective backend, active count, simulation/render submission averages, wall-clock FPS, framebuffer dimensions and grid resolution. Frames run independently inside equal-size documents, avoiding surface clipping/stacking interference. This page is not imported by production startup.

9. Performance: `node tools/paint-quality-benchmark.mjs` runs identical looping inputs, 120 warmup frames and 600 measured frames per backend. This desktop run: Standard 224 particles, mean 2.51 ms, median 1.96 ms, p95 6.56 ms; High 1,800 particles, mean 1.06 ms, median 0.65 ms, p95 2.88 ms. High's coarse grid avoids Standard's individual neighbour checks. Foreground browser samples after warmup showed roughly 1.4–2.3 ms simulation / 0.7–1.6 ms render submission for Standard, versus 0.5–1.3 / 0.2–1.3 ms for High; cold samples were higher (around 2–4 ms per stage). The comparison reached about 60 FPS in foreground; background tabs throttle to about 1 FPS. Submission timing is not GPU completion, and these are baselines, not cross-device guarantees. No mobile hardware benchmark was performed.

10. Visual observations: browser comparison exercised slow, fast, sharp-turn and loop inputs, pan and 200% zoom. High has a visibly denser, softer suspended medium and more continuous-looking deformation. Fast motion remains bound, without long streaks or spray; both lag around curves. High's coarse pressure can form grain/clumps, and its flow is still a spring/grid approximation. A real drag in the High Simple Playtest app created a Paint phrase through the existing commit path with no High initialization warning after the shader/compositing fixes. Standard's production renderer module was unchanged; its tests and side-by-side output passed. After a browser-control interruption, a fresh session completed deterministic pause/release checks: both presentations settled, dimmed and reached zero active particles. Resize changed the High framebuffer from 839?818 to 499?507 and back; viewport overrides were reset. The hole begins filling during release rather than bursting. Automated tests also cover exclusion, transforms, DPR/framebuffer resize, inward settling, resource release, and zero scheduled work after expiry.

11. Assessment: High improves density and softness enough to retain as an independent experiment. It is not yet evidence for broader WebGL migration: convincing syrup-like closure and natural curling remain uncertain. Keep Standard as the safe playtest default and continue comparing both.

12. Next: High is already selectable for the active Paint gesture in the real app. Before promoting it, refine wake closure and clumping, test mobile GPUs and forced context loss in browsers, capture GPU timing where supported, and tune coarse-grid clumping and wake closure. Rendering authored Paint paths/nodes through the same shared state is a separate future step; no other toys have been migrated.

Validation: 37 focused tests pass across runtime presets, quality parsing, shared inputs/colour/radius, fallback/reduced motion/cancelled load, actual identical authored commit payloads, drawing/Scissors/instrument behaviour, Standard particles, and High alignment/resize/shared surface/idle disposal. `git diff --check` passes. Quality does not enter the actual commit payload; no persistence or musical implementation was changed. A full save/reload browser round trip was not manually performed.
